# tdb (mini-gdb)

Linux x86-64向けの、学習・検証用ミニマルソースレベルデバッガです。
`ptrace(2)`によるプロセス制御、ELFシンボル解析、DWARFデバッグ情報解析
（行番号テーブル・変数・型情報）を外部デバッグライブラリ（libdwarf等）
に依存せず自前実装しています。

## 主な機能

- ブレークポイント（アドレス/シンボル名/`file:line`指定）、ステップ実行
  （命令単位/ソース行単位/ステップオーバー/関数リターンまで実行）
- ハードウェアウォッチポイント（値変化検知、読み書きアクセス監視）
- 変数・式評価（構造体/配列/ポインタ、メンバアクセス、`p/x`等の書式指定）
- レジスタ表示・代入（汎用レジスタ、x87/SSE浮動小数点レジスタ含む）
- マルチスレッド対応（`threads`/`thread`、スレッドごとのブレークポイント/
  ウォッチポイント伝播、オールストップ同期）
- スケジューラロック（`lock <tid>`/`unlock`）による単一スレッド実行制御
- マルチプロセス対応（`fork`/`vfork`で生成された子プロセスの自動追跡）
- ヒープトレース／メモリリーク検出（`malloc`/`free`/`calloc`/`realloc`）
- ソース表示・逆アセンブル（`objdump`連携）、DWARF情報の直接参照（`dbg`系）
- PIE/非PIE両対応、SIGINTのデバッギーへの転送

コマンド解析・式評価は`bison`/`flex`が利用可能な環境ではそれらで生成した
パーサを使用し、無い環境では自前実装のパーサへ自動的にフォールバックし
ます（いずれの構成でも同一のコマンド仕様を満たします）。

## ビルド

```sh
make
```

`tdb`本体と、動作確認用のサンプルデバッギー（`target`/`leak_target`/
`thread_target`/`fork_target`）が生成されます。`bison`/`flex`が入って
いれば自動検出して利用し、無ければ内蔵パーサにフォールバックします。

```sh
make clean   # 生成物一式を削除
```

## 使い方

```sh
./tdb
(tdb) run target
(tdb) b add
(tdb) c
(tdb) p x
(tdb) regs
(tdb) tb
(tdb) q
```

対応コマンドの一覧は`(tdb) help`で確認できます。主なものの例:

| コマンド | 例 | 概要 |
|---|---|---|
| `run` | `run <program>` | デバッギー起動 |
| `b` / `break` | `b add` / `b file.c:10` / `b 0x401000` | ブレークポイント設置 |
| `c` / `s` / `si` / `n` / `up` | | 継続 / 行ステップイン / 命令ステップ / 行ステップオーバー / リターンまで実行 |
| `p` / `print` | `p x` / `p/x x` | 式評価・表示 |
| `set` | `set x = 1` / `set $rax = 0` | 変数・レジスタへの代入 |
| `watch` | `watch x` / `watch /r expr` | ハードウェアウォッチポイント設置 |
| `threads` / `thread` | `thread 2` | スレッド一覧・切替 |
| `lock` / `unlock` | `lock <tid>` | 指定スレッドのみ実行するロック |
| `regs` / `tb` / `syms` | | レジスタ・バックトレース・シンボル一覧表示 |
| `show` | `show bp` / `show locals` / `show leaks` | 各種状態表示 |
| `dis` / `l` / `list` | `dis add` / `list add` | 逆アセンブル・ソース表示 |
| `kill` / `q` | | デバッギー強制終了 / `tdb`終了 |

マルチスレッド（`thread_target.c`）・マルチプロセス（`fork_target.c`）
確認用のサンプルは、それぞれのソースコード先頭コメントに具体的な操作例
を記載しています。

## 制約・既知の限界

- 対応OS/アーキテクチャはLinux x86-64のみ
- `fork`/`vfork`した子プロセスは元と同一の実行ファイルを実行し続けること
  を前提とする（子プロセスによる`execve`での別プログラムへの切り替えは
  追跡対象外）
- ヒープトレースはメインスレッド／元プロセスのみを対象とする
- リモートデバッグ（別ホスト上のプロセスへのアタッチ）には対応しない
- ブレークポイント最大32個、ウォッチポイント最大4個（x86デバッグ
  レジスタDR0-DR3の制約）、シンボル最大1024個、同時追跡スレッド/プロセス
  最大64個などの固定上限あり

詳細は[01_要件定義書.md](docs/01_要件定義書.md)の「制約事項・前提条件」
「スコープ外事項」を参照してください。
