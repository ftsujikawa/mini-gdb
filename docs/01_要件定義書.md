# 要件定義書

- 文書名: tdb（mini-gdb）要件定義書
- 対象システム: `tdb`（Linux x86-64 向け ミニデバッガ）
- バージョン: 1.5
- 作成日: 2026-07-07
- 更新日: 2026-07-15

---

## 1. 文書の目的

本書は、C言語で実装されたミニマルなソースレベルデバッガ `tdb`（プロジェクト名 mini-gdb）について、実現すべき機能・非機能要件および制約事項を定義するものである。以降の基本設計書・詳細設計書・テスト仕様書は、本書の要件を出発点として作成する。

## 2. 背景・目的

- `tdb` は、Linux x86-64 上で動作する ELF 実行ファイル（DWARF デバッグ情報付き）を対象とした、GDB に似た機能を持つ最小構成のコマンドラインデバッガである。
- `ptrace(2)` によるプロセス制御、ELF シンボルテーブル解析、DWARF 情報解析（行番号テーブル・変数・型情報）を自前実装し、外部デバッグライブラリ（libdwarf 等）に依存しない。
- 学習・検証目的および軽量なデバッグ用途（ブレークポイント、ステップ実行、変数参照、簡易リーク検出）を主眼とする。

## 3. 用語定義

| 用語 | 説明 |
|---|---|
| デバッガ / tdb | 本システム本体（実行バイナリ名 `tdb`） |
| デバッギー（debuggee） | デバッグ対象として起動される子プロセス |
| REPL | Read-Eval-Print Loop。`(tdb)` プロンプトによる対話コマンド入力ループ |
| DWARF | ELF に格納されるデバッグ情報フォーマット |
| PIE | Position Independent Executable。実行時にロードアドレスが変動する実行ファイル |
| ロードベース | PIE バイナリが実際にロードされた仮想アドレスの基準値 |
| ブレークポイント | 実行を一時停止させる位置に埋め込む INT3（0xCC）命令 |
| lvalue | 代入（`set`）可能な式（変数・メンバ・配列要素・デリファレンス結果など） |
| ヒープトレース | `malloc`/`free`/`calloc`/`realloc` 呼び出しをフックして確保・解放状況を追跡する機能 |

## 4. 想定利用者・利用環境

- 利用者: C言語プログラムの動作解析・デバッグを行う開発者（本システム自体の開発者を含む）。
- 利用環境:
  - OS: Linux（x86-64）
  - デバッグ対象: ELF 実行ファイル（`gcc -g` 等でコンパイルされ DWARF 情報を含むもの、非PIE/PIE 双方）
  - 実行形態: ターミナル上での対話的コマンドライン操作（REPL）
  - ビルド環境: `gcc`、`make`。`bison`/`flex` は任意（無い場合は自前実装のパーサにフォールバック）
  - 逆アセンブル表示には外部コマンド `objdump` を利用する

## 5. 機能要件

### 5.1 プロセス起動・実行制御

| ID | 要件 |
|---|---|
| FR-01 | 利用者は `run <program>` により、指定した実行ファイルを子プロセスとして起動し、`ptrace` によるトレース対象とできること |
| FR-02 | 起動時、対象が PIE バイナリであれば `/proc/<pid>/maps` からロードベースアドレスを取得し、以降のアドレス変換に用いること |
| FR-03 | 利用者は `c` により、停止中のデバッギーの実行を再開できること |
| FR-04 | 利用者は `si` により、機械語命令単位で1命令だけ実行できること |
| FR-05 | 利用者は `s` により、ソース行単位で1行だけ実行できること（関数呼び出しの内部にも入る） |
| FR-06 | 利用者は `n` により、関数呼び出しをまたいでソース行単位で1行実行できること（呼び出し先には入らない）。分岐（`if`等）により実際の実行が行番号順で連続しない次の行を飛び越える場合でも、真に実行された次の行（または関数からの復帰時は呼び出し元の行）で正しく停止すること |
| FR-07 | 利用者は `up` により、現在の関数を最後まで実行して呼び出し元に戻ることができること |
| FR-08 | デバッギーがシグナル受信や正常終了・異常終了した場合、その旨をREPL上に表示すること |
| FR-09 | 利用者は `kill` により、実行中のデバッギーを強制終了できること。終了後もデバッガ自体（`tdb`）は継続動作し、`run` により新たにデバッギーを起動できること。デバッギー未起動時に `kill` を実行した場合はエラーメッセージを表示すること |
| FR-16 | デバッギーの実行継続中（`c` コマンド待機中）に利用者が Ctrl+C（SIGINT）を入力した場合、デバッガはその SIGINT をデバッギープロセスに転送し、デバッギーの実行を中断できること。中断後はデバッガのプロンプトに戻り、通常のコマンド操作を継続できること |

### 5.2 ブレークポイント

| ID | 要件 |
|---|---|
| FR-10 | 利用者は `b`/`break <addr\|symbol\|file:line>` により、アドレス・シンボル名・ファイル名と行番号の指定でブレークポイントを設定できること |
| FR-11 | シンボル名指定の場合、関数プロローグ通過後のアドレスに設定すること |
| FR-12 | ブレークポイントは最大 32 個まで設定できること。上限を超える場合はエラーメッセージを表示し失敗すること |
| FR-13 | 利用者は `show bp` により、設定済みブレークポイントの一覧（番号・有効フラグ・アドレス・対応関数・file:line）を確認できること |
| FR-14 | ブレークポイント到達時、実行を一時停止し、停止位置（ソース行）を表示すること |
| FR-15 | 利用者は `del`/`delete <num>` により、`show bp` で表示される番号でブレークポイントを削除できること |

### 5.2a ウォッチポイント

| ID | 要件 |
|---|---|
| FR-15a | 利用者は `watch <expr>` により、変数・構造体メンバ・配列要素・デリファレンス結果等のlvalue式に対しハードウェアウォッチポイントを設定できること。対象アドレスの値が実際に変化した時点で実行を一時停止し、変化前後の値（`Old value` / `New value`）を型に応じた形式で表示すること |
| FR-15b | ウォッチポイントの監視サイズは対象式の型サイズから自動決定すること。型サイズが 1・2・4・8 バイトのいずれでもない場合（構造体等）はエラーとし、設定を拒否すること |
| FR-15c | 利用者は `watch /1`\|`/2`\|`/4`\|`/8 <expr>` により、監視サイズを明示的に指定できること。型サイズによらずこの指定が優先されること |
| FR-15d | 利用者は `watch /r <expr>` により、書き込みに加え読み取りアクセスも検知する監視（アクセスウォッチポイント）を設定できること。読み取りは値が変化しないため、通常の書込監視と異なり値の変化有無によらず毎回停止・報告すること |
| FR-15e | ウォッチポイントは x86 ハードウェアデバッグレジスタ（DR0-DR3）を用いるため、同時に設定できる数は最大 4 個までとすること。上限を超える場合はエラーメッセージを表示し失敗すること |
| FR-15f | 利用者は `show watch` により、設定済みウォッチポイントの一覧（番号・有効フラグ・アドレス・サイズ・監視モード・対象式）を確認できること |
| FR-15g | 利用者は `del`/`delete w<num>` により、`show watch` で表示される番号でウォッチポイントを削除できること。削除後は残りのウォッチポイントを詰めてデバッグレジスタへ再設定すること |
| FR-15h | デバッギーの強制終了（`kill`）・正常終了・新規 `run` の際、それまでに設定されたウォッチポイントの状態を破棄し、新しいプロセスに引き継がないこと（ハードウェアデバッグレジスタはプロセス単位のため） |

### 5.3 変数・式評価

| ID | 要件 |
|---|---|
| FR-20 | 利用者は `p`/`print [/fmt] <expr>` により、C言語風の式（識別子、`.`/`->`メンバアクセス、`[]`添字、`*`/`&`、四則演算・比較・論理演算・ビット演算、`$reg`レジスタ参照など）を評価し結果を表示できること |
| FR-21 | 表示フォーマットとして 10進・16進・8進・2進・符号無し・char・文字列・ポインタを指定できること |
| FR-22 | 利用者は `set <lvalue> = <expr>` により、変数・構造体メンバ・配列要素・レジスタへ値を代入できること |
| FR-22a | 利用者は `set $<reg> = <expr>` により、汎用レジスタに加えx87制御語（`fctrl`/`fstat`/`ftag`/`fop`）・`mxcsr`・x87スタックレジスタ（`st0`-`st7`）・SSEレジスタ（`xmm0`-`xmm15`）へ値を代入できること。`st0`-`st7`/`xmm0`-`xmm15` は10進小数（例: `3.4`）を指定するとIEEE754浮動小数点値として、`0x`接頭の値を指定すると生のビットパターンとして代入されること |
| FR-23 | 利用者は `show locals`/`show args`/`show globals` により、現在のスコープにおけるローカル変数・引数・グローバル変数の一覧と値を確認できること |
| FR-24 | 構造体・配列・文字列（char配列/char*）は、それぞれに適した形式で整形表示できること |
| FR-25 | 利用者は表示設定（`set print format/array/pretty/elements`、`set output-radix`、`set language c`）を変更でき、`show`（引数無し）または `show print` で現在の設定を確認できること |

### 5.4 デバッグ情報・ソース表示

| ID | 要件 |
|---|---|
| FR-30 | 利用者は `l`/`list [line\|file:line\|function]` により、指定位置周辺のソースコードを表示できること。引数省略時は現在の停止位置を基準とすること |
| FR-31 | 利用者は `dis <function\|file:line\|line\|addr>` により、指定範囲の逆アセンブル結果を表示できること（内部で `objdump` を利用） |
| FR-32 | 利用者は `dbg vars`/`dbg var <name>`/`dbg lines [file]`/`dbg line <loc>` により、DWARF から取得した変数一覧・個別変数詳細・行番号テーブル・特定位置のデバッグ情報を確認できること |
| FR-33 | 利用者は `lines [file]` により、DWARF行番号テーブルの内容を確認できること |

### 5.5 実行状態の参照

| ID | 要件 |
|---|---|
| FR-40 | 利用者は `regs` により、汎用レジスタ・セグメントレジスタ・フラグレジスタ・x87浮動小数点レジスタ（制御語/状態語/タグワード/`st0`-`st7`）・SSEレジスタ（`mxcsr`/`xmm0`-`xmm15`）と現在の停止位置（ソース行）を確認できること |
| FR-41 | 利用者は `tb` により、フレームポインタ（rbp）チェーンをたどったバックトレース（最大32フレーム）を表示できること |
| FR-42 | 利用者は `syms` により、ロード済みELFシンボル（関数・オブジェクト、アドレス、サイズ）の一覧を確認できること |
| FR-43 | 利用者は `x <addr>` により、指定アドレスのメモリ内容（1ワード）を確認できること |

### 5.6 ヒープトレース／リーク検出

| ID | 要件 |
|---|---|
| FR-50 | 利用者は `set heap-trace on/off` により、デバッギー内の `malloc`/`free`/`calloc`/`realloc` 呼び出しの追跡有効/無効を切り替えられること |
| FR-51 | 追跡有効時、各確保呼び出しについてサイズ・呼び出し元位置（file:line、可能な場合）・返却ポインタを記録すること |
| FR-52 | `free` 呼び出し時、対応する確保記録を解放済みとして扱うこと |
| FR-53 | 利用者は `show heap` により、現時点で生存中（未解放）の確保一覧を確認できること |
| FR-54 | 利用者は `show leaks` により、生存中の確保をリーク候補として一覧表示できること |
| FR-55 | デバッギープロセス終了時、リーク件数のサマリを自動表示すること |
| FR-56 | 追跡対象の確保記録は最大 4096 件、フック対象関数は最大 4 個（malloc/free/calloc/realloc）とすること |
| FR-57 | ヒープフックによる一時停止は利用者に明示的なブレークポイント到達として見せず、内部で自動的に実行継続すること（透過的な計測） |

### 5.7 REPL・コマンドライン

| ID | 要件 |
|---|---|
| FR-60 | 利用者は対話プロンプト `(tdb)` 上で1行1コマンド形式によりデバッガを操作できること |
| FR-61 | 利用者は `help` により、対応コマンドの一覧と簡単な説明を確認できること |
| FR-62 | 利用者は `q` により、デバッガを終了できること（実行中のデバッギーが存在する場合の扱いは基本設計で定める） |
| FR-63 | 不正なコマンド・引数の場合はエラーメッセージを表示し、REPLは継続すること（デバッガ自体は異常終了しないこと） |
| FR-64 | コマンド解析は「自前実装（`cmd.c`）」と「bison/flex 生成実装（`cmd_parser.y`/`cmd_lexer.l` → `cmd_bison.c`）」の2系統を持ち、ビルド時に `bison`/`flex` の有無で自動的に切り替わること。両実装は同一のコマンド仕様（`del`/`delete` を含む）を満たすこと |

## 6. 非機能要件

| ID | 要件 |
|---|---|
| NFR-01 | 対応OS/アーキテクチャは Linux x86-64 に限定する |
| NFR-02 | 外部ライブラリ依存を持たず、標準Cライブラリと `ptrace`/ELF関連のシステムヘッダのみで実装すること（逆アセンブルのみ外部コマンド `objdump` に依存） |
| NFR-03 | ビルドは `make` 一発で完結し、`bison`/`flex` が無い環境でもフォールバック実装によりビルド・動作可能なこと |
| NFR-04 | 内部データ（ブレークポイント、シンボル、行テーブル、変数、型キャッシュ、ヒープ確保記録）は固定長配列で管理し、上限超過時は動的確保を行わずエラー表示または静かな打ち切りとすること（設計上の既知の制約として明記する） |
| NFR-05 | 1コマンドの処理過程で発生したエラーはREPL全体をクラッシュさせず、当該コマンドの失敗として処理を継続できること |
| NFR-06 | ソースコードは機能単位でファイル分割し、各モジュールの責務が明確であること |

## 7. 制約事項・前提条件

- 対応 DWARF 機能は本システムが解釈するタグ・属性・フォーム（`dbg.h` に定義された `DW_TAG_*`/`DW_AT_*`/`DWARF_FORM_*` 一覧）に限定されるサブセットであり、全DWARF仕様を網羅しない。
- 構造体メンバは1型あたり最大16個までしか保持できない（`type_info_t.members[16]`）。
- ブレークポイント最大32個、シンボル最大1024個、行テーブルエントリ最大4096個、変数最大256個、型キャッシュ最大128個、ヒープ確保記録最大4096件という固定上限が存在し、それを超える規模のプログラムでは情報が切り捨てられる。
- マルチスレッドのデバッギーは想定しない（単一プロセス・単一スレッドの `ptrace` 制御を前提とする）。
- リモートデバッグ（別ホスト上のプロセスのアタッチ）には対応しない。
- `run` はデバッギーへのコマンドライン引数（argv）受け渡しに対応しない（プログラムパスのみ指定可能）。

## 8. スコープ外事項

- Windows/macOS 等、他OS・他アーキテクチャへの対応
- GUIフロントエンドの提供
- マルチスレッド/マルチプロセスデバッグ、条件付きブレークポイント、ウォッチポイント
- DWARF全機能（インライン展開情報、最適化情報等）への対応
- ネットワーク経由のリモートデバッグプロトコル（gdbserver相当）
