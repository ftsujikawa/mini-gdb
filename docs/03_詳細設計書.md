## 2. dbg_globals.c / dbg.h

### 2.1 処理内容
- `dbg.h` は本プロジェクトの中核ヘッダであり、以下を定義する。

## 4. memory.c

| 関数 | 処理内容 |
|---|---|
| `read_memory(addr)` | `PTRACE_PEEKDATA` で1ワード読み取る。失敗時は `errno` を判定し `perror` |
| `peek_word(addr, *value)` / `poke_word(addr, value)` | 読み取り/書き込みの成否を戻り値（0/-1）で返すラッパー。ブレークポイントのINT3埋め込み・復元、ヒープフック設置で使用 |
| `read_target_byte(addr, *out)` | `peek_word` の結果から1バイトを抜き出す。文字列表示（`print_string_value`）などバイト単位アクセスに使用 |
| `examine_memory(addr)` | `x` コマンド本体。`peek_word` で1ワード取得し16進数で表示する |

処理フロー（`x <addr>` 実行時）:
1. `ui.c` の `handle()` が `CMD_X` を受け取り、引数を16進アドレスとしてパース
2. `examine_memory(addr)` を呼び出し、`peek_word` で値取得
3. 取得失敗時はエラーメッセージ、成功時はアドレスと値を整形出力

## 5. exec.c

### 5.1 プロセス起動 `run_target(program)`
1. `debuggee_path`/`debuggee_realpath` を設定
2. `fork()`。子プロセス側は `PTRACE_TRACEME` → `execl(program, ...)`
3. 親プロセスは `waitpid` で最初の停止（execによるSIGTRAP）を待機
4. `load_symbols`・`load_line_table`・`load_variables` を呼び、ELF/DWARF情報をロード
5. ELFヘッダから PIE(`ET_DYN`) かどうかを判定し、PIEなら `update_load_base()` で `/proc/<pid>/maps` を解析してロードベースを設定
6. `heap_trace_enabled()` が真であれば `heap_reset()` → `heap_arm_hooks()` を実行し、ヒープフックを設置
7. `dbg.pid`/`dbg.running` を設定し、起動完了

### 5.2 ステップ実行
- `single_step()`: `PTRACE_SINGLESTEP` を1回発行し、`waitpid` で停止を待つ（`si`コマンド）
- `source_step()`: 現在の`file:line`を記録した上で、最大10000命令まで `single_step` を繰り返し、`lookup_line` の結果が変化した時点で停止する（`s`コマンド）。ブレークポイントに命中した場合は途中で停止する
- `next_line()`: `lookup_next_line_scoped` により現在関数スコープ内での「次の行」のアドレスを求め、`next_bp` に一時ブレークポイントとして設置後 `continue_execution` を呼び出す（`n`コマンド）。関数呼び出しの内部には一時ブレークポイントを置かないため、呼び出し先を素通りする

### 5.3 ブレークポイント管理
| 関数 | 処理内容 |
|---|---|
| `set_breakpoint(addr)` | `bp_count >= MAX_BREAKPOINTS` チェック→ 対象アドレスの1バイトを `original_data` に退避 → `0xCC` を書き込み → `breakpoints[]` に登録 |
| `find_breakpoint(addr)` / `find_breakpoint_by_rip(rip)` | アドレス一致するブレークポイントをリニアサーチ |
| `restore_breakpoint(bp)` | 退避しておいた元データをアドレスに書き戻す |
| `enable_breakpoint(bp)` | INT3を再設置する |
| `rewind_rip(addr)` | INT3ヒット後、`rip`をブレークポイントアドレスに補正する（レジスタ設定） |
| `step_over_breakpoint(bp)` | 元データへ復元 → 1命令だけ `single_step` → INT3を再設置、の3手順でブレークポイント位置を安全に通過させる |

### 5.4 `finish`（`up`）/`next` ヒット処理
- `get_return_address(*ret_addr)`: 現在のスタック/`rbp`チェーンから呼び出し元へのリターンアドレスをヒューリスティックに取得する
- `finish_function()`: `get_return_address` で戻り先を求め、`finish_bp` に一時ブレークポイントとして設置し `continue_execution` を呼ぶ
- `handle_finish_hit()` / `handle_next_hit()`: `continue_execution` のトラップ処理内から呼ばれ、一時ブレークポイントの復元・`finish_bp`/`next_bp` の非活性化・停止位置表示を行う

### 5.5 実行継続 `continue_execution()`
処理フロー:
1. ユーザーブレークポイント位置で停止していれば `step_over_breakpoint` で1回通過させる
2. `PTRACE_CONT` で実行再開し、`waitpid` で次の停止を待つループに入る
3. 停止要因ごとに以下の優先順で処理する
   1. `heap_handle_finish_trap(&regs)` — ヒープフックの確保完了トラップか判定し、該当すれば記録して自動継続
   2. `heap_handle_trap(&regs)` — ヒープフック（malloc/free等エントリ）のトラップか判定し、該当すれば処理して自動継続
   3. `next_bp`/`finish_bp` のアドレスと一致するか判定し、該当すれば `handle_next_hit`/`handle_finish_hit` を呼んで停止
   4. ユーザーブレークポイント（`find_breakpoint_by_rip`）に一致すれば `rewind_rip` の上で停止し、停止位置を表示
4. デバッギーが `WIFEXITED`/`WIFSIGNALED` した場合は `heap_on_process_exit()` を呼んでリークサマリを表示し、`dbg.running = 0` とする

### 5.6 バックトレース補助
- `show_backtrace()`（ui.c）から利用される `rbp` チェーン走査自体はui.c側にあるが、リターンアドレス取得の基本ロジックは `get_return_address` と共通の考え方（スタック上のリターンアドレス候補を行テーブルと突き合わせる）に基づく。

## 6. dwarf.c

### 6.1 略語テーブル・DIE解析
1. `.debug_abbrev` を読み込み、コンパイル単位ごとに `MAX_ABBREVS(64)` 件を上限として略語コード→タグ/属性リストの対応表を構築
2. `.debug_info` をDIEツリーとして先頭から走査（`parse_dies`）し、DIEごとに以下を判定
   - `DW_TAG_compile_unit`: コンパイル単位の基準情報（低位/高位アドレス等）取得
   - `DW_TAG_subprogram`: 関数の範囲（`low_pc`/`high_pc`）取得。以降の子DIE（引数・ローカル変数）のスコープ判定に使用
   - `DW_TAG_variable` / `DW_TAG_formal_parameter`: `var_entry_t` を構築し `vars[]` に追加（`add_var_entry`、上限 `MAX_VARS`）
   - `DW_TAG_base_type`/`pointer_type`/`structure_type`/`array_type`/`typedef`/`const_type`: 型情報として `type_info_t` を構築

### 6.2 型情報解析
- `get_cached_type(off, *out)`: `type_cache[]` を線形探索し、キャッシュ済みならそれを返す。無ければDIEをその場で解析してキャッシュに追加（`MAX_TYPE_CACHE`到達後はキャッシュされず毎回再解析）
- `resolve_type_alias`: `typedef`/`const_type`の連鎖をたどり実体の型オフセットへ解決する
- `lookup_pointer_type(ref_off)`: 指定型を指すポインタ型のDIEオフセットを検索する
- 構造体メンバは `dwarf_member_t members[16]` に格納するため、16個を超えるメンバを持つ構造体は超過分が無視される

### 6.3 変数解決
- `lookup_var(name, rip)`: `vars[]` を走査し、名前が一致し、かつ `rip` が `scope_low`〜`scope_high` の範囲内（グローバル変数はスコープ制限なし）にあるエントリを返す
- 変数の実アドレスは `loc` により2通り
  - `VAR_FBREG`: フレームベース相対（`DW_OP_fbreg` + `fbreg`）。実アドレスは実行時のフレームベースレジスタ値から算出
  - `VAR_ADDR`: 絶対アドレス（`DW_OP_addr`）。PIEの場合は `to_runtime_addr` で補正

### 6.4 行番号テーブル
- `load_line_table(path)`: `.debug_line`のプログラムをステートマシンとして実行し、アドレス→(file, line)の対応を `line_entries[]` に追加（`MAX_LINE_ENTRIES`上限）。あわせて `line_addr_min`/`line_addr_max` を更新
- `lookup_line(addr, *file, *line)`: 指定アドレス以下で最も近い行エントリを検索
- `lookup_line_addr(file, line, *addr)`: file:line指定からアドレスを逆引き（ブレークポイント設置・`list`コマンドで使用）
- `lookup_next_line` / `lookup_next_line_scoped`: 現在行より後の次の行エントリを検索。`_scoped`版は現在の関数スコープ内に限定（`next`コマンドで使用）
- `show_line_table(file_filter)`: `lines`コマンド本体。全エントリまたは指定ファイルのみを整形表示

### 6.5 `dbg`コマンド群
- `dbg_command(args)`: 引数（`vars`/`var <name>`/`lines [file]`/`line <loc>`）を解析し、対応する表示処理へ分岐する

## 8. expr.c（式評価・コマンド本体）

### 8.1 主な内部状態
- `print_settings_t`: `language`（現状`c`のみ）、`format`（decimal/hex/octal/binary/unsigned/char/string/pointer）、`array`（on/off）、`pretty`（on/off）、`elements`（unlimited または上限数）を保持する静的設定

### 8.2 値表示
| 関数 | 処理内容 |
|---|---|
| `print_value` | 型情報(`type_info_t`)と生値をもとに、種別（BASE/POINTER/STRUCT/ARRAY/ALIAS）に応じた表示へ分岐 |
| `print_struct_value` | メンバを順に読み出し `{ .member = value, ... }` 形式（`pretty`設定により改行/インデント切替）で表示 |
| `print_array_value` | 要素型・要素数に従い添字ごとに値を表示（`elements`上限に達したら省略表示） |
| `print_string_value` | `char*`/`char[]` を対象に、`read_target_byte`でヌル終端まで読み出し文字列として表示 |

### 8.3 式パーサ・評価器（`#ifndef HAVE_EXPR_BISON` の場合のみ有効）
- `ep_parse_*` 系関数群による再帰下降パーサ（優先順位: 単項 → 乗除 → 加減 → シフト → 比較 → 等価 → ビットAND/XOR/OR → 論理AND/OR）
- 識別子は `lookup_var(name, rip)` によるDWARF変数解決、失敗時はレジスタテーブル（`$reg`名）参照を試みる
- `.`/`->`/`[]`/単項`&`・`*`の適用によりlvalue/型を更新しながら評価する

### 8.4 コマンド本体
| 関数 | 処理内容 |
|---|---|
| `print_expression(expr)` | `p`/`print`コマンド本体。`/fmt`接頭辞を`parse_print_format`で解釈後、式を評価し`print_value`等で出力 |
| `set_command(args)` | `set $<reg> = <expr>`（レジスタ代入）、`set <lvalue> = <expr>`（メモリ代入）、`set language/output-radix/print .../heap-trace ...`（各種設定変更）を判別して処理する |
| `show_command(args)` | `show`（引数無しで表示設定一覧）、`show language/print/bp/heap/leaks`を判別し分岐。`bp`は`exec.c`の一覧表示、`heap`/`leaks`は`heap.c`の`show_heap`/`show_leaks`を呼ぶ |
| `show_locals()` / `show_args()` / `show_globals()` | `vars[]`を`kind`とスコープでフィルタし、現在の`rip`に対応する値を`print_value`で表示 |

### 8.5 bison利用時の間接化
- `HAVE_EXPR_BISON`定義時、`eval_expression_any`/`eval_lvalue_any`/`expr_to_ulong_any`（内部マクロ/薄いラッパ）が `eval_expression_bison`/`eval_lvalue_bison`/`expr_to_ulong_bison`（expr_eval_ast.c）を呼び出す形に切り替わり、`print_expression`/`set_command`の呼び出し側コードは変更不要とする設計。

## 9. expr_ast.c/.h, expr_parse.c, expr_eval_ast.c, expr_parser.y, expr_lexer.l（bison経路）

- `expr_lexer.l`: 数値（10進/16進/8進）、識別子、`$`付きレジスタ名、記号トークンを字句解析する flex 定義
- `expr_parser.y`: C言語相当の演算子優先順位で式を構文解析し、`expr_ast_t`ツリーを構築する bison 文法（単項 `+ - ! ~ & *`、二項 `* / % + - << >> < <= > >= == != & ^ | && ||`、後置`.`/`->`/`[]`）
- `expr_ast.c`/`.h`: ASTノード（数値・識別子・レジスタ・単項/二項演算・メンバアクセス・添字）のコンストラクタ・破棄関数を提供
- `expr_parse.c`: `expr_parse_ast(str)` が `expryy_scan_string` + `expryyparse()` を呼び出し、成功時にASTルートを返す。失敗時は `expr_parse_error` に理由を格納
- `expr_eval_ast.c`: ASTを再帰的に評価する。識別子ノードは `lookup_var` → レジスタテーブルの順で解決し、`eval_expression_bison`/`eval_lvalue_bison`/`expr_to_ulong_bison` として `dbg.h` 宣言のAPIを実装する

## 10. cmd.c / cmd_bison.c / cmd_parser.y / cmd_lexer.l（コマンド解析）

### 10.1 共通API
```c
int cmd_parse_line(const char *line, cmd_t *out, char *errbuf, size_t errbufsz);
void cmd_free(cmd_t *cmd);
```
戻り値0で成功（空行/空白行は `CMD_INVALID` として成功扱い）。`out->arg` はヒープ確保された残余引数文字列（無ければNULL）。

### 10.2 cmd.c（手書き実装）
1. 先頭空白を読み飛ばし、最初の単語（コマンド名）を切り出す
2. コマンド名を `cmd_kind_t` にマッピング（文字列比較テーブル）
3. 残りの文字列を`trim_line`した上で`arg`として複製（`dup_str`。失敗時は`errbuf`に"out of memory"を設定）
4. 未知のコマンド名は `CMD_INVALID` + エラーメッセージを設定して返す

### 10.3 cmd_bison.c + cmd_parser.y/cmd_lexer.l（生成実装）
- `cmdyyparse()`（`api.prefix {cmdyy}`でシンボル名衝突を回避）が文法規則に基づきコマンドを認識する
- `cmd_lexer.l` は `list`/`dis`/`break`/`show`/`dbg`/`lines`/`x`/`print`/`set` 等、自由形式の引数を取るコマンドを認識した時点で `<ARG>` 排他開始条件に遷移し、以降の文字列をコマンドキーワードとして再トークナイズしないようにする
- `cmd_bison.c` が `cmd_parse_line`/`cmd_free` を実装し、`cmd.c`と同一のインタフェースを提供する（同時にはリンクされない）

## 11. ui.c（REPL・表示）

### 11.1 メインループ `repl()`
1. `printf("(tdb) ")` でプロンプト表示
2. 標準入力から1行読み込み（EOFで終了）
3. `handle(line)` を呼び出す
4. ループを継続

### 11.2 `handle(line)` のディスパッチ
1. `cmd_parse_line` で `cmd_t` に変換。失敗時はエラーメッセージ表示して終了
2. `switch (cmd.kind)` で全コマンド種別を分岐し、各モジュールの実装関数を呼び出す
   - `CMD_RUN` → `run_target`
   - `CMD_C` → `continue_execution`
   - `CMD_S`/`CMD_SI`/`CMD_N`/`CMD_UP` → `source_step`/`single_step`/`next_line`/`finish_function`
   - `CMD_BREAK` → 引数を addr/symbol/file:line のいずれかに判別し `set_breakpoint`（またはシンボル/行解決）
   - `CMD_SHOW` → `show_command`（内部で`bp`は`show_breakpoints`、`locals/args/globals`はexpr.c側）
   - `CMD_DBG`/`CMD_LINES` → `dbg_command`/`show_line_table`
   - `CMD_LIST` → `list_source`
   - `CMD_DIS` → `disassemble_command`
   - `CMD_TB` → `show_backtrace`
   - `CMD_REGS` → `show_regs`
   - `CMD_SYMS` → `show_symbols`
   - `CMD_X` → `examine_memory`
   - `CMD_PRINT` → `print_expression`
   - `CMD_SET` → `set_command`
   - `CMD_HELP` → `show_help`
   - `CMD_QUIT` → `exit(0)`
3. `cmd_free(&cmd)` で引数バッファを解放

### 11.3 ソース表示
- `show_source_listing(file, line)`: 指定ファイルを開き、`line`を中心に前後5行を表示する
- `list_source(arg)`: 引数（数値行／file:line／関数名）を解析し、必要ならDWARF/シンボルからアドレス・行を逆引きしてから `show_source_listing` を呼ぶ。引数省略時は現在の`rip`に対応する行を使用
- `show_stop_location(pc)` / `show_pc_location(rip)`: ブレークポイントヒット・ステップ後に現在行を1行表示する

### 11.4 逆アセンブル
- `disassemble_command(arg)`: 引数を関数名/file:line/行番号/アドレスのいずれかとして解決し、対象アドレス範囲を算出
- 内部で `popen("objdump -d ...")` を実行し、出力をアドレスでフィルタしながら表示する。PIEの場合はアドレスを `to_debug_addr`/`to_runtime_addr` で変換して対応づける

### 11.5 レジスタ・バックトレース表示
- `show_regs()`: `PTRACE_GETREGS` で `user_regs_struct` を取得し、汎用レジスタ・セグメントレジスタ・`eflags` を整形表示。あわせて現在の`rip`に対応するfile:lineも表示する
- `show_backtrace()`: 現在の`rbp`から開始し、`[rbp]`を次のフレームの`rbp`、`[rbp+8]`をリターンアドレスとして辿るフレームポインタチェーン走査を最大32回繰り返す。各フレームで`lookup_function_symbol`によりシンボル名を解決し出力する

## 12. heap.c / heap.h（ヒープトレース）

### 12.1 内部状態
- `heap_allocs[MAX_HEAP_ALLOCS]`: 各エントリは `live`（生存フラグ）・`kind`（malloc/calloc/realloc種別）・`ptr`・`size`・`seq`（通番）・`call_site`（呼び出し元file:line文字列）等を持つ
- フック管理テーブル（最大`MAX_HEAP_HOOKS=4`）: `malloc`/`free`/`calloc`/`realloc`それぞれのエントリアドレスとINT3退避データ
- `heap_finish_bp`（`finish_bp_t`型を静的に再利用）: 確保系フックの戻り値待ち一時ブレークポイント

### 12.2 フック設置 `heap_arm_hooks()`
1. `malloc`/`free`/`calloc`/`realloc`について、`lookup_symbol_entry`で実シンボルを検索し、無ければ`lookup_plt_symbol`（`<name>@plt`）で代替
2. 見つかったアドレスに対し、ブレークポイントと同じ手順（1バイト退避 → INT3書込）でフックを設置
3. `heap_disarm_hooks()`はその逆手順で全フックを復元する

### 12.3 トラップ処理
- `heap_handle_trap(regs)`（エントリトラップ）
  1. `regs->rip - 1` が登録フックアドレスと一致するか判定。一致しなければ0を返し呼び出し元（`continue_execution`）に処理を委ねる
  2. 一致すれば `rewind_rip` 相当の補正を行い、対象関数の引数（`rdi`/`rsi`等のABIレジスタ、`malloc`はサイズ、`calloc`は`nmemb*size`、`realloc`は旧ポインタ+新サイズ、`free`は対象ポインタ）を読み取る
  3. `free`は即座に`heap_record_free(ptr)`で対応記録を非生存化して終了（戻り値待ち不要）
  4. `malloc`/`calloc`/`realloc`は `heap_find_call_site()`（`rbp`チェーン及びスタック上位64ワードを走査し、行テーブルに存在する最初の候補アドレスを呼び出し元とみなすヒューリスティック）で呼び出し元を推定した上で引数を保存し、`step_over_breakpoint`相当の処理でフック命令を1回通過させ、戻り先アドレスに`heap_finish_bp`を設置する
  5. 処理した場合は1を返し、`continue_execution`は表向きの停止を発生させず実行を継続する
- `heap_handle_finish_trap(regs)`（確保完了トラップ）
  1. `heap_finish_bp`がアクティブかつ現在の停止位置が一致するか判定
  2. 一致すれば`rax`を返却ポインタとして取得し、保存しておいた種別・サイズ・呼び出し元情報とあわせて`heap_record_alloc()`を呼び出し新規記録を`live=1`で追加（`realloc`の場合は旧ポインタの記録を`heap_record_free`してから新規追加）
  3. 一時ブレークポイントを復元し、フック済みエントリアドレスにINT3を再設置する

### 12.4 表示
- `show_heap()` / `show_leaks()`: `heap_allocs[]`を走査し`live==1`のエントリのみ、通番・ポインタ値・サイズ・種別・呼び出し元file:line（取得できた場合）を一覧表示する。両者は同じデータソースを異なる見出しで表示するのみで、リークは「その時点で生存中の確保」として近似的に扱う
- `heap_on_process_exit()`: デバッギー終了検知時（`exec.c`の`continue_execution`から呼ばれる）に、`live`エントリ数と合計バイト数を集計し「N leak(s), 合計サイズ」のサマリを表示する

### 12.5 exec.cとの結合点
| 呼び出し元 | 呼び出し関数 | タイミング |
|---|---|---|
| `run_target` | `heap_reset()` → `heap_arm_hooks()`（トレース有効時のみ） | プロセス起動直後 |
| `continue_execution` のトラップハンドラ | `heap_handle_finish_trap` → `heap_handle_trap` | 各SIGTRAP停止時、ユーザーブレークポイント判定より前 |
| `continue_execution` の終了検知 | `heap_on_process_exit()` → `heap_disarm_hooks()` | `WIFEXITED`/`WIFSIGNALED`検知時 |

## 13. 例外・エラー処理詳細（共通方針の適用箇所）

| 分類 | 代表箇所 | 処理 |
|---|---|---|
| ptrace/システムコール失敗 | `memory.c`の`peek_word`/`poke_word`、`exec.c`の`waitpid` | `errno`判定 + `perror` + `-1`/`void`復帰 |
| 容量超過 | `set_breakpoint`（`bp_count>=MAX_BREAKPOINTS`）、`heap_record_alloc`（`heap_alloc_count>=MAX_HEAP_ALLOCS`）、`add_var_entry`、`load_symbols`のループ条件 | 事前チェックにより書き込みをスキップ。ブレークポイントのみ明示メッセージ、他は静かな打ち切り |
| 利用者エラー | `ui.c`の各コマンドハンドラ | `printf`での短文メッセージ、REPL続行 |
| パースエラー | `cmd_parse_line`, `expr_parse_ast`/bison版 | `errbuf`/静的エラーバッファへメッセージ格納、呼び出し元が表示 |
| プロセス終了 | `continue_execution` | `dbg.running=0`、ヒープサマリ表示のみで異常終了しない |
| 明示終了 | `ui.c`の`CMD_QUIT`処理 | `exit(0)` を唯一のプロセス終了経路とする |
