## 4. memory.c

| 関数 | 処理内容 |
|---|---|
| `read_memory(addr)` | `read_memory_tid(dbg.pid, addr)` の薄いラッパー |
| `read_memory_tid(tid, addr)` | `PTRACE_PEEKDATA` で指定tidから見た1ワードを読み取る。失敗時は `errno` を判定し `perror`。全スレッドが同一アドレス空間を共有するため読み取り結果自体はどのtidを指定しても同じだが、`PTRACE_PEEKDATA` は対象tidが現在ptrace停止中でなければ失敗（`ESRCH`）するため、マルチスレッド環境では「今まさに停止していると判明しているtid」を明示的に渡す必要がある場面（`check_watchpoints`等）のために公開されている |
| `peek_word(addr, *value)` / `poke_word(addr, value)` | 読み取り/書き込みの成否を戻り値（0/-1）で返すラッパー。ブレークポイントのINT3埋め込み・復元、ヒープフック設置で使用 |
| `read_target_byte(addr, *out)` | `peek_word` の結果から1バイトを抜き出す。文字列表示（`print_string_value`）などバイト単位アクセスに使用 |
| `examine_memory(addr)` | `x` コマンド本体。`peek_word` で1ワード取得し16進数で表示する |

処理フロー（`x <addr>` 実行時）:
1. `ui.c` の `handle()` が `CMD_X` を受け取り、引数を16進アドレスとしてパース
2. `examine_memory(addr)` を呼び出し、`peek_word` で値取得
3. 取得失敗時はエラーメッセージ、成功時はアドレスと値を整形出力

## 5. exec.c

### 5.1 プロセス起動 `run_target(program)`
0. `wp_count = 0` を設定する（ハードウェアデバッグレジスタはプロセス単位の状態であり、新しいデバッギーには前回の設定が引き継がれないため）
1. `fork()`。子プロセス側は `PTRACE_TRACEME` → `raise(SIGSTOP)` → `execl(program, ...)`
2. 親プロセスは `waitpid` で子の `SIGSTOP` 停止を待機する
3. `debuggee_path`/`debuggee_realpath` を設定（`realpath`でフルパス取得を試みる）
4. `load_symbols`・`load_line_table`・`load_variables` を呼び、ELF/DWARF情報をロード
5. `wait_for_exec(pid)` を呼び出す。この関数は `PTRACE_SETOPTIONS` で `PTRACE_O_TRACEEXEC` と `PTRACE_O_TRACECLONE`（マルチスレッド対応。以後のスレッド生成を`PTRACE_EVENT_CLONE`として検知するため）を設定し、`PTRACE_CONT` を発行して `PTRACE_EVENT_EXEC` による停止を最大5回のループで待つ
6. `update_load_base()` で `/proc/<pid>/maps` を解析してロードベースを設定（非PIEの場合はすぐ0のまま返る）
7. `dbg.running = 1` を設定する。`dbg.current_tid = pid` とし、`threads[]` を初期化して `threads[0] = {tid: pid, active: 1, running: 0}`、`thread_count = 1` とする（メインスレッドを唯一のスレッドとして登録した状態で開始する）
8. `heap_reset()` を無条件に呼び出した後、`heap_trace_enabled()` が真であれば `heap_arm_hooks()` を実行しヒープフックを設置する
9. 起動完了メッセージ（`[+] process started pid=N`）を表示する

### 5.1a プロセス強制終了 `kill_process()`（`kill`コマンド）
1. `dbg.running` が偽なら「no process」を表示して終了
2. `next_bp`/`finish_bp`/`step_over_bp`（5.2節参照）を`disarm_temp_breakpoint`で解除し、`heap_disarm_hooks()`でヒープフックも解除する（内部状態を確実にクリーンな状態へ戻す。ptraceによるINT3復元処理自体はプロセスが直後に消滅するため実質的な影響は無いが、`active`フラグ等の内部状態リセットのため実行する）
3. `kill(dbg.pid, SIGKILL)` でデバッギー（スレッドグループ全体）を強制終了する。`SIGKILL`はスレッド単位ではなくプロセス全体を終了させる特別な信号であるため、追跡中の全スレッドが終了する
4. `thread_count`（キル発行時点で追跡していたスレッド数）分の `WIFEXITED`/`WIFSIGNALED` イベントを `waitpid(-1, &status, __WALL)` で回収するまでリトライし、いずれのスレッドもゾンビ化させない
5. `wp_count = 0`、`thread_count = 0` を設定してウォッチポイント・スレッド一覧をクリアする（デバッグレジスタ・スレッドは死んだプロセスとともに消滅するため）
6. `dbg.running = 0` を設定し、「[+] process killed (pid=N)」を表示する。`tdb`自体は終了せず、以後`run`で新たなデバッギーを起動できる

### 5.2 ステップ実行
- `single_step()`: `PTRACE_SINGLESTEP` を1回発行し、`waitpid` で停止を待つ（`si`コマンド）
- `source_step()`: 現在の`file:line`を記録した上で、最大10000命令まで `single_step` を繰り返し、`lookup_line` の結果が変化した時点で停止する（`s`コマンド）。ブレークポイントに命中した場合は途中で停止する
- `next_line()`（`n`コマンド）: 現在の`file:line`と`rsp`を記録し、`PTRACE_SINGLESTEP`による1命令単位のループ（上限100000回）で実行する。各ステップの直前に `insn_is_call(rip)` で命令オペコードを判定し、`call`命令（近接相対呼び出し`0xE8`、または近接間接呼び出し`0xFF /2`・`/3`）であれば、ステップ実行後にスタック上の戻り先アドレスへ内部専用の一時ブレークポイント`step_over_bp`を設置して`continue_execution()`を呼び、呼び出し先の内部を素通りする（ブレークポイント・ヒープフックへの命中は`continue_execution`側で通常通り検知され、その場合は`next`もそこで終了する）。`call`でない命令は通常通り1命令だけ進める。各ステップ後、`lookup_line`の結果が開始時と異なり、かつ`rsp`が開始時点以上（同じかそれより浅いスタック深さ）になった時点で停止する。この判定により、`if`等の分岐で行番号順の「次の行」が実行時にスキップされるケースや、関数の`return`で呼び出し元に復帰するケースも正しく検出できる

### 5.3 ブレークポイント管理
| 関数 | 処理内容 |
|---|---|
| `set_breakpoint(addr)` | `bp_count >= MAX_BREAKPOINTS` チェック→ 対象アドレスの1バイトを `original_data` に退避 → `0xCC` を書き込み → `breakpoints[]` に登録 |
| `find_breakpoint(addr)` / `find_breakpoint_by_rip(rip)` | アドレス一致するブレークポイントをリニアサーチ |
| `restore_breakpoint(bp)` / `restore_breakpoint_tid(tid, bp)` | 退避しておいた元データをアドレスに書き戻す。前者は`dbg.pid`固定、後者は明示的にtidを指定する版（マルチスレッド対応で追加） |
| `enable_breakpoint(bp)` / `enable_breakpoint_tid(tid, bp)` | INT3を再設置する。tid指定版は同上の理由で追加 |
| `rewind_rip(tid, addr)` | INT3ヒット後、指定tidの`rip`をブレークポイントアドレスに補正する（レジスタ設定） |
| `step_over_breakpoint(tid, bp)` | 指定tidに対し、元データへ復元 → `rewind_rip` → 1命令だけシングルステップ → INT3を再設置、の手順でブレークポイント位置を安全に通過させる。シングルステップは、他スレッド同期用に送信済みの`SIGSTOP`等の保留中シグナルによって命令が実際には実行されずに（`rip`が進まずに）復帰してしまうことがあるため、`PTRACE_GETREGS`で`rip`が実際に進んだことを確認できるまで最大10回リトライする（`restore_breakpoint_tid`/`rewind_rip`は既に完了しているため、何度リトライしても安全） |
| `delete_breakpoint(num)` | 番号（1始まり）でブレークポイントを削除する。対象の `enabled` フラグが真なら `restore_breakpoint` でINT3を除去し、`breakpoints[]` 配列の後続エントリを詰めて `bp_count` を減算する。番号が範囲外の場合はエラーメッセージを表示して -1 を返す |
| `show_breakpoints()` | `bp_count == 0` の場合は「no breakpoints」を表示。0以上なら「Num / Enb / Address / What」のヘッダ付きで番号・有効状態・アドレス・シンボル名・file:lineを整形表示する |

### 5.3a ウォッチポイント管理
| 関数 | 処理内容 |
|---|---|
| `peek_debugreg(tid, i)` / `poke_debugreg(tid, i, val)` | `PTRACE_PEEKUSER`/`PTRACE_POKEUSER` により、指定tidの `struct user.u_debugreg[i]`（`DR0`-`DR7`相当）を読み書きする。デバッグレジスタはプロセス単位ではなくスレッド単位のCPU状態であるため、マルチスレッド対応で全て明示的なtid指定に変更された |
| `mask_for_size(size, value)` | `value` の下位 `size` バイトのみを残すマスク処理。ウォッチポイントの値比較・表示で、監視対象より広い8バイトワード読み取り結果から余分な隣接データを除去するために使う |
| `dr7_len_bits(size)` | 監視サイズ（1/2/4/8バイト）を `DR7` のLENフィールド値（`00`/`01`/`11`/`10`）に変換する |
| `arm_watch_slot(tid, slot, addr, size, access_mode)` | 指定tidの指定スロット（0-3）の `DR0`-`DR3` に監視アドレスを設定し、`DR7` の該当スロットのL（ローカル有効）・R/W（`access_mode`が真なら`11`＝読み書き、偽なら`01`＝書込のみ）・LENの各フィールドを設定する |
| `disarm_watch_slot(tid, slot)` | 指定tidの `DR7` の該当スロットのL/G有効ビットのみをクリアする（`DR0`-`DR3`の値自体は残るが無効化される） |
| `propagate_watchpoints_to_thread(tid)` | 現在アクティブな全ウォッチポイント（`watchpoints[0..wp_count)`）を指定tidに`arm_watch_slot`で適用する。新規スレッド生成時（`continue_execution`のSIGSTOPハンドラ）に呼ばれ、ハードウェアウォッチポイントをプロセス内の全スレッドに行き渡らせる |
| `watch_command(args)` | `watch`コマンド本体。`parse_watch_flags`で先頭の`/r`・`/1`〜`/8`フラグ（結合・分離どちらの記法も可）を解釈した後、`resolve_lvalue`で式をアドレス・型へ解決する。監視サイズはフラグ指定があればそれを優先し、無ければ型サイズ（1/2/4/8バイト以外は不可としてエラー）を用いる。`wp_count`が`MAX_WATCHPOINTS(4)`未満であることを確認し、空きスロットについて追跡中の**全スレッド**へ`arm_watch_slot`を適用後、初期値を`mask_for_size`で読み取って`watchpoints[]`に登録する |
| `parse_watch_flags(args, *access_mode, *size_override)` | 先頭の`/`始まりトークンを読み進め、`r`/`R`文字で読み書きアクセス監視、`1`/`2`/`4`/`8`文字で監視サイズ上書きを解釈する。未知の文字がある場合はusageメッセージを表示しNULLを返す |
| `show_watchpoints()` | `wp_count == 0` の場合は「no watchpoints」を表示。0以上なら「Num / Enb / Address / Size / Mode / What」のヘッダ付きで一覧表示する（Modeは`w`＝書込のみ、`rw`＝読み書き） |
| `delete_watchpoint(num)` | 番号（1始まり）でウォッチポイントを削除する。追跡中の**全スレッド**について対象スロットを`disarm_watch_slot`で無効化した後、後続エントリを配列上で詰め、詰めた各エントリを新しいスロット番号で全スレッドに対し`arm_watch_slot`により再設置する（デバッグレジスタのスロット番号と配列インデックスを一致させ続けるため） |
| `check_watchpoints(tid, *regs)` | `continue_execution`のSIGTRAP処理から呼ばれる。`wp_count == 0`なら即座に0を返す。指定tidの`DR6`を読み取り、ビット0-3（各スロットのヒットフラグ）のみをマスクして参照する（ビット4-13はハードウェア仕様上常に1が立つ予約ビットのため、マスクしないと通常のINT3ヒット等あらゆるSIGTRAPを誤ってウォッチポイントヒットと誤認してしまう）。ヒットしたスロットごとに現在値を`read_memory_tid(tid, ...)`と`mask_for_size`で読み取り、書込のみ監視（`access_mode`偽）は値が変化した場合のみ、読み書き監視（`access_mode`真）は常に、`print_watch_value`（expr.c）でOld/New値を表示する。処理後は指定tidの`DR6`を0に書き戻す。戻り値は「0=ウォッチポイント要因ではない」「1=値変化を検出・報告済み（呼び出し元は停止）」「2=スプリアスヒット（呼び出し元は自動継続）」。メモリ読み取りに`read_memory`（常に`dbg.pid`）ではなく`read_memory_tid(tid, ...)`を使うのは、マルチスレッド環境ではヒットしたtid以外（`dbg.pid`含む）がまだ実行中である可能性があり、停止していないtidに対する`PTRACE_PEEKDATA`は失敗するため |

### 5.4 `finish`（`up`）/`next` ヒット処理
- `get_return_address(*ret_addr)`: 現在のスタック/`rbp`チェーンから呼び出し元へのリターンアドレスをヒューリスティックに取得する
- `finish_function()`: `get_return_address` で戻り先を求め、`finish_bp` に一時ブレークポイントとして設置し `continue_execution` を呼ぶ
- `handle_finish_hit()` / `handle_next_hit()`: `continue_execution` のトラップ処理内から呼ばれ、一時ブレークポイントの復元・`finish_bp`/`next_bp` の非活性化・停止位置表示を行う

### 5.5 実行継続 `continue_execution()`（マルチスレッド対応・オールストップ方式）
処理フロー:
1. 追跡中の全スレッド（`threads[]`）に対し `PTRACE_CONT` を発行して再開し、各エントリの `running` を1にする
2. `for(;;)` ループで `waitpid(-1, &status, __WALL)` により、いずれかのスレッドの次の停止を待つ（特定のtidではなく `-1` を指定することで、追跡中のどのスレッドの停止イベントも捕捉できる）。`waitpid` はEINTRリトライループで包み、`sigint_handler` によるシグナル割り込みでも待機を継続する
3. `WIFEXITED`/`WIFSIGNALED` の場合:
   - 停止した tid が `dbg.pid`（メインスレッド）と一致する場合、プロセス全体の終了とみなす。`next_bp`/`finish_bp`/`step_over_bp` の一時ブレークポイントを解除 → `heap_on_process_exit()` → `heap_disarm_hooks()` → `wp_count = 0` → `thread_count = 0` → `dbg.running = 0` で終了
   - それ以外（非メインスレッドの終了）は `remove_thread(tid)` で追跡対象から除外し、ループを継続する
4. `WIFSTOPPED` の場合、シグナル番号を取得し、以下の優先順で処理する
   1. `SIGTRAP` かつ `PTRACE_EVENT_CLONE` イベント（`(status >> 16) & 0xffff`）の場合: `PTRACE_GETEVENTMSG` で新規スレッドのtidを取得し `add_thread` で登録する（**この時点ではまだ `PTRACE_CONT` で再開しない**。新規スレッド自身の初回停止通知〈後述〉と本通知はどちらが先に届くか不定であり、再開は次項のSIGSTOPハンドラに一元化する）。通知元スレッドは `PTRACE_CONT` で再開し `continue`（利用者には見せない）
   2. `SIGSTOP` の場合: `add_thread(tid)`（未登録なら登録）した上で、そのスレッドが `running` フラグ上「停止中」であれば、`propagate_watchpoints_to_thread` で既存の全ウォッチポイントを適用してから `PTRACE_CONT` で再開する。SIGSTOPは「新規スレッドの初回停止」または「`sync_stop_other_threads` が送った同期用SIGSTOP」以外の理由では発生しないため、常に内部処理として扱い利用者には見せない
   3. `check_watchpoints(tid, &regs)` が1を返せば `dbg.current_tid = tid` として `sync_stop_other_threads(tid)` を呼び停止、2を返せば当該tidを `PTRACE_CONT` して `continue`（スプリアスヒットの自動継続）
   4. `heap_handle_finish_trap(&regs)` / `heap_handle_trap(&regs)` が1を返せば当該tidを `PTRACE_CONT` して `continue`（自動継続）
   5. `tid == dbg.current_tid` かつ `step_over_bp`/`next_bp`/`finish_bp` のいずれかがアクティブでヒットしていれば、対応する `handle_temp_stop`/`handle_next_hit`/`handle_finish_hit` を呼び、`sync_stop_other_threads(tid)` を実行して返る（これらの一時ブレークポイントは常に「選択中スレッド」に対する `n`/`up` 操作に紐づくため、`tid` が選択中スレッドと一致する場合のみ処理する）
   6. `find_breakpoint_by_rip(regs.rip)` でユーザーブレークポイントに一致すれば: `add_thread(tid)`（防御的登録）→ `dbg.current_tid = tid` → `sync_stop_other_threads(tid)` → 一時ブレークポイントを解除 → 停止位置を表示 → `step_over_breakpoint(tid, bp)` を実行して返る
   7. いずれにも一致しない場合、`tid != dbg.current_tid` なら見過ごしてよいものとして `PTRACE_CONT` で再開し `continue`（他スレッドの不明な単発トラップで `c` を止めない）。`tid == dbg.current_tid` の場合は `sync_stop_other_threads(tid)` を実行してシグナル番号と停止位置を表示し返る

### 5.5a オールストップ同期 `sync_stop_other_threads(stopped_tid)`
- いずれかのスレッド（`stopped_tid`）が利用者に見せる停止イベントを起こした際、他の全スレッドも一時停止させ、プロセス全体が停止した状態でプロンプトに戻る（gdbの既定動作と同様）。
- `threads[]` を走査し、`stopped_tid` 以外の `running` なスレッドそれぞれに `syscall(SYS_tgkill, dbg.pid, tid, SIGSTOP)` を送って停止させ、送信した数を `pending` に記録する。
- `pending` が0になるまで `waitpid(-1, &status, __WALL)` を繰り返し、各イベントを次のように処理する。
  - `WIFEXITED`/`WIFSIGNALED`: `pending` を減算し `remove_thread`
  - 未登録のtid（親スレッドの `PTRACE_EVENT_CLONE` 通知がまだ本関数の外側〈`continue_execution`〉に届いていない）: `add_thread` で登録し、`SIGSTOP` 以外なら `step_over_if_pending_breakpoint` を適用する（`pending` には最初から含まれていないため減算しない）
  - 登録済みで `running` なスレッド: `running = 0` とし `pending` を減算する。受信したシグナルが `SIGSTOP` でない場合（＝このスレッドが送った同期用SIGSTOPより先に自分自身の要因で停止していた場合）、`step_over_if_pending_breakpoint(tid)` を呼ぶ。ブレークポイント上で停止していなければ（戻り値0）、送信済みの `SIGSTOP` がまだキューに残っており次回再開時に横取りする可能性があるため、`PTRACE_CONT` で再開して即座に `waitpid` で回収する

### 5.5b ブレークポイント途中停止の解消 `step_over_if_pending_breakpoint(tid)`
- 指定tidの現在の `rip` が既知のブレークポイントのINT3直後（`find_breakpoint_by_rip`が一致）であれば `step_over_breakpoint(tid, bp)` を呼んで正しく通過させ、1を返す。一致しなければ何もせず0を返す。
- 複数スレッドがほぼ同時に同じブレークポイントへ到達した場合や、スレッド生成直後に即座にブレークポイントへ到達した場合など、「登録・処理される前に他の経路でこのtidの停止イベントだけ先に観測される」ケースに対する保険であり、`sync_stop_other_threads` 内の複数箇所から呼ばれる。放置すると、当該スレッドの `rip` がINT3の1バイト先に留まったまま次に再開され、ブレークポイントが後で削除された場合などに元の命令の途中から実行を再開して実行が破壊される（不正な命令列の実行によるクラッシュ）。

### 5.6 バックトレース補助
- `show_backtrace()`（ui.c）から利用される `rbp` チェーン走査自体はui.c側にあるが、リターンアドレス取得の基本ロジックは `get_return_address` と共通の考え方（スタック上のリターンアドレス候補を行テーブルと突き合わせる）に基づく。

### 5.7 スレッド管理
| 関数 | 処理内容 |
|---|---|
| `find_thread_index(tid)` | `threads[0..thread_count)` を線形探索し、`tid`が一致し`active`なエントリのインデックスを返す（無ければ-1） |
| `add_thread(tid)` | `find_thread_index`で既存なら0を返して何もしない（冪等）。`thread_count >= MAX_THREADS(64)`ならエラーメッセージを表示して-1を返す。それ以外は`threads[thread_count]`に`{tid, active:1, running:0}`を設定し`thread_count`を増やす |
| `remove_thread(tid)` | 該当エントリを配列上で詰めて`thread_count`を減算する。`dbg.current_tid`が削除対象だった場合は`threads[0].tid`（詰めた後の先頭スレッド）に切り替える。非メインスレッドの終了時（`continue_execution`）や`sync_stop_other_threads`内での終了検知時に呼ばれる |
| `show_threads()` | `thread_count == 0`なら「no threads」を表示。それ以外は「Id / Tid」のヘッダ付きで一覧表示し、`dbg.current_tid`と一致する行の先頭に`*`を付ける（`threads`コマンド本体） |
| `switch_thread(num)` | 番号（1始まり、`threads`で表示される番号）が範囲外なら「invalid thread number」を表示して-1を返す。範囲内なら`dbg.current_tid`を該当tidに更新し、`PTRACE_GETREGS`で取得した`rip`を`show_stop_location`に渡して現在位置を表示する（`thread <num>`コマンド本体） |

## 6. dwarf.c

### 6.1 略語テーブル・DIE解析
1. `.debug_abbrev` を読み込み、コンパイル単位ごとに `MAX_ABBREVS(64)` 件を上限として略語コード→タグ/属性リストの対応表を構築
2. `.debug_info` をDIEツリーとして先頭から走査（`parse_dies`）し、DIEごとに以下を判定
   - `DW_TAG_compile_unit`: コンパイル単位の基準情報（低位/高位アドレス等）取得
   - `DW_TAG_subprogram`: 関数の範囲（`low_pc`/`high_pc`）取得。以降の子DIE（引数・ローカル変数）のスコープ判定に使用
   - `DW_TAG_variable` / `DW_TAG_formal_parameter`: `var_entry_t` を構築し `vars[]` に追加（`add_var_entry`、上限 `MAX_VARS`）
   - `DW_TAG_base_type`/`pointer_type`/`structure_type`/`array_type`/`typedef`/`const_type`: 型情報として `type_info_t` を構築

### 6.2 型情報解析
- `get_cached_type(off, *out)`: `type_cache[]` を線形探索し、キャッシュ済みならそれを返す。無ければDIEをその場で解析してキャッシュに追加（`MAX_TYPE_CACHE`到達後はキャッシュされず毎回再解析）
- `resolve_type_alias`: `typedef`/`const_type`の連鎖をたどり実体の型オフセットへ解決する
- `lookup_pointer_type(ref_off)`: 指定型を指すポインタ型のDIEオフセットを検索する
- 構造体メンバは `dwarf_member_t members[16]` に格納するため、16個を超えるメンバを持つ構造体は超過分が無視される

### 6.3 変数解決
- `lookup_var(name, rip)`: `vars[]` を走査し、名前が一致し、かつ `rip` が `scope_low`〜`scope_high` の範囲内（グローバル変数はスコープ制限なし）にあるエントリを返す
- 変数の実アドレスは `loc` により2通り
  - `VAR_FBREG`: フレームベース相対（`DW_OP_fbreg` + `fbreg`）。実アドレスは実行時のフレームベースレジスタ値から算出
  - `VAR_ADDR`: 絶対アドレス（`DW_OP_addr`）。PIEの場合は `to_runtime_addr` で補正

### 6.4 行番号テーブル
- `load_line_table(path)`: `.debug_line`のプログラムをステートマシンとして実行し、アドレス→(file, line)の対応を `line_entries[]` に追加（`MAX_LINE_ENTRIES`上限）。あわせて `line_addr_min`/`line_addr_max` を更新
- `lookup_line(addr, *file, *line)`: 指定アドレス以下で最も近い行エントリを検索
- `lookup_line_addr(file, line, *addr)`: file:line指定からアドレスを逆引き（ブレークポイント設置・`list`コマンドで使用）
- `lookup_next_line`: 指定ファイル内で現在行より後の次の行エントリを検索するユーティリティ（現時点でコマンド処理からは呼び出されていない）
- `show_line_table(file_filter)`: `lines`コマンド本体。全エントリまたは指定ファイルのみを整形表示

### 6.5 `dbg`コマンド群
- `dbg_command(args)`: 引数（`vars`/`var <name>`/`lines [file]`/`line <loc>`）を解析し、対応する表示処理へ分岐する

## 10. cmd.c / cmd_bison.c / cmd_parser.y / cmd_lexer.l（コマンド解析）

### 10.1 共通API
```c
int cmd_parse_line(const char *line, cmd_t *out, char *errbuf, size_t errbufsz);
void cmd_free(cmd_t *cmd);
```
戻り値0で成功（空行/空白行は `CMD_INVALID` として成功扱い）。`out->arg` はヒープ確保された残余引数文字列（無ければNULL）。

### 10.2 cmd.c（手書き実装）
1. 先頭空白を読み飛ばし、最初の単語（コマンド名）を切り出す
2. コマンド名を `cmd_kind_t` にマッピング（文字列比較テーブル）。認識コマンド: `run`/`c`/`s`/`si`/`n`/`up`/`regs`/`syms`/`tb`/`l`・`list`/`dis`/`b`・`break`/`del`・`delete`/`show`/`dbg`/`lines`/`x`/`p`・`print`/`set`/`help`/`q`
3. 残りの文字列を末尾改行を除去した上で`arg`として複製（失敗時は`errbuf`に"out of memory"を設定）。`del`/`delete` を含む引数付きコマンドは `CMD_DEL` にマッピングし、`arg` に番号文字列を格納する
4. 未知のコマンド名は `errbuf` に "unknown command" を設定して -1 を返す

### 10.3 cmd_bison.c + cmd_parser.y/cmd_lexer.l（生成実装）
- `cmdyyparse()`（`api.prefix {cmdyy}`でシンボル名衝突を回避）が文法規則に基づきコマンドを認識する
- `cmd_lexer.l` は `list`/`dis`/`break`/`b`/`delete`/`del`/`show`/`dbg`/`lines`/`x`/`print`/`p`/`set` 等、自由形式の引数を取るコマンドを認識した時点で `<ARG>` 排他開始条件に遷移し、以降の文字列をコマンドキーワードとして再トークナイズしないようにする。`<ARG>` 状態では先頭の空白をスキップし、残り全体（改行まで）を `T_REST` トークンとして返す
- `cmd_parser.y` では `T_DEL T_REST opt_eol` / `T_DELETE T_REST opt_eol` の規則で `CMD_DEL` を生成する
- `cmd_bison.c` が `cmd_parse_line`/`cmd_free` を実装し、`cmd.c`と同一のインタフェースを提供する（同時にはリンクされない）

## 11. ui.c（REPL・表示）

### 11.1 シグナルハンドラ `sigint_handler(sig)` および `main()` 初期化

- `main()` は REPL 開始前に `signal(SIGINT, sigint_handler)` を呼び出し、`SIGINT`（Ctrl+C）のハンドラを登録する。
- `sigint_handler(sig)` の処理:
  1. `dbg.running` が真かつ `dbg.pid > 0` であれば `kill(dbg.pid, SIGINT)` を呼び出し、SIGINT をデバッギーに転送する。
  2. 上記条件を満たさない場合（デバッギーが起動していない、またはすでに終了している）は何もしない。これにより、プロンプト待機中に Ctrl+C を押してもデバッガ自体が終了しない。
- `show_help()` には `Ctrl+C  interrupt running program` の説明行を追加する。

### 11.2 メインループ `repl()`
1. `printf("(tdb) ")` でプロンプト表示
2. 標準入力から1行読み込み（EOFで終了）
3. `handle(line)` を呼び出す
4. ループを継続

### 11.3 `handle(line)` のディスパッチ
1. `cmd_parse_line` で `cmd_t` に変換。失敗時はエラーメッセージ表示して終了
2. `switch (cmd.kind)` で全コマンド種別を分岐し、各モジュールの実装関数を呼び出す
   - `CMD_RUN` → `run_target`
   - `CMD_C` → `continue_execution`
   - `CMD_S`/`CMD_SI`/`CMD_N`/`CMD_UP` → `source_step`/`single_step`/`next_line`/`finish_function`
   - `CMD_KILL` → `kill_process`
   - `CMD_THREADS` → `show_threads`
   - `CMD_THREAD` → 引数を数値として解析し `switch_thread(num)` を呼び出す。数値でない場合は usage メッセージを表示
   - `CMD_BREAK` → 引数を addr/symbol/file:line のいずれかに判別し `set_breakpoint`（またはシンボル/行解決）
   - `CMD_WATCH` → `watch_command`（引数が空の場合はui.c側でusageメッセージ）
   - `CMD_DEL` → 引数が `w`/`W` で始まれば残りを数値として解析し `delete_watchpoint(num)` を、それ以外は `delete_breakpoint(num)` を呼び出す。数値でない場合は usage メッセージを表示
   - `CMD_SHOW` → `show_command`（内部で`bp`は`show_breakpoints`、`watch`は`show_watchpoints`、`locals/args/globals`はexpr.c側）
   - `CMD_DBG`/`CMD_LINES` → `dbg_command`/`show_line_table`
   - `CMD_LIST` → `list_source`
   - `CMD_DIS` → `disassemble_command`
   - `CMD_TB` → `show_backtrace`
   - `CMD_REGS` → `show_regs`
   - `CMD_SYMS` → `show_symbols`
   - `CMD_X` → `examine_memory`
   - `CMD_PRINT` → `print_expression`
   - `CMD_SET` → `set_command`
   - `CMD_HELP` → `show_help`
   - `CMD_QUIT` → `exit(0)`
3. `cmd_free(&cmd)` で引数バッファを解放

### 11.4 ソース表示
- `show_source_listing(file, line)`: 指定ファイルを開き、`line`を中心に前後5行を表示する
- `list_source(arg)`: 引数（数値行／file:line／関数名）を解析し、必要ならDWARF/シンボルからアドレス・行を逆引きしてから `show_source_listing` を呼ぶ。引数省略時は現在の`rip`に対応する行を使用
- `show_stop_location(pc)` / `show_pc_location(rip)`: ブレークポイントヒット・ステップ後に現在行を1行表示する。表示の先頭で「`[+] pid=N tid=M`」を出力する。`N`は`dbg.pid`（スレッドグループID）、`M`は`dbg.current_tid`（当該停止に関与した具体的なスレッド。マルチスレッドデバッギーでは両者が異なる値になる）

### 11.5 逆アセンブル
- `disassemble_command(arg)`: 引数を関数名/file:line/行番号/アドレスのいずれかとして解決し、対象アドレス範囲を算出
- 内部で `popen("objdump -d ...")` を実行し、出力をアドレスでフィルタしながら表示する。PIEの場合はアドレスを `to_debug_addr`/`to_runtime_addr` で変換して対応づける

### 11.6 レジスタ・バックトレース表示
- `show_regs()`: `PTRACE_GETREGS` で（`dbg.current_tid`の）`user_regs_struct` を取得し、汎用レジスタ・セグメントレジスタ・`eflags` を整形表示。あわせて現在の`rip`に対応するfile:lineも表示する。続けて `PTRACE_GETFPREGS` で `user_fpregs_struct` を取得し、x87制御語（`fctrl`/`fstat`/`ftag`/`fop`/`fioff`/`fooff`）・SSE制御（`mxcsr`/`mxcsr_mask`）・x87スタックレジスタ`st0`-`st7`（`st_space`の各16バイトを`long double`として再解釈した値と生バイト列を表示）・SSEレジスタ`xmm0`-`xmm15`（`xmm_space`の各16バイトを128bit生値と`{v2_double = {lo, hi}}`形式の2要素doubleとして表示）を出力する
- `show_backtrace()`: `dbg.current_tid`の現在の`rbp`から開始し、`[rbp]`を次のフレームの`rbp`、`[rbp+8]`をリターンアドレスとして辿るフレームポインタチェーン走査を最大32回繰り返す。各フレームで`lookup_function_symbol`によりシンボル名を解決し出力する

## 12. heap.c / heap.h（ヒープトレース）

### 12.1 内部状態
- `heap_allocs[MAX_HEAP_ALLOCS]`（`heap_alloc_t`型）: 各エントリは次のフィールドを持つ
  - `ptr`（`unsigned long`）: 確保ポインタ
  - `size`（`unsigned long`）: 確保バイト数
  - `live`（`int`）: 生存フラグ（1=未解放、0=解放済み）
  - `kind`（`heap_hook_kind_t`）: `HEAP_HOOK_MALLOC`/`HEAP_HOOK_CALLOC`/`HEAP_HOOK_REALLOC` のいずれか
  - `seq`（`unsigned long`）: 確保順序通番
  - `call_site`（`unsigned long`）: 呼び出し元アドレス（表示時に `lookup_line` でfile:lineへ変換）
- フック管理テーブル（`heap_hook_t`型、最大`MAX_HEAP_HOOKS=4`）: `armed`フラグ・`kind`（`heap_hook_kind_t`）・`addr`・`original_data` を保持
- 待機状態: `heap_wait`（`HEAP_IDLE`/`HEAP_WAIT_RET` の2値）と `heap_wait_kind`/`heap_wait_size`/`heap_wait_old`/`heap_wait_site` で確保途中の引数を保持
- `heap_finish_bp`（`finish_bp_t`型を静的に再利用）: 確保系フックの戻り値待ち一時ブレークポイント

### 12.2 公開 API（heap.h）

| 関数 | 処理内容 |
|---|---|
| `heap_reset()` | フックカウント・確保記録・通番・待機状態・`heap_finish_bp` を全リセット |
| `heap_on_process_exit()` | プロセス終了時のリークサマリ表示（`heap_trace_on` が偽の場合は無処理） |
| `heap_trace_enabled()` | 現在のトレース有効フラグ（0/1）を返す |
| `heap_set_trace(on)` | トレース有効/無効を切り替える。プロセス実行中なら即座にフックの設置/解除も行う |
| `heap_arm_hooks()` | 各ヒープ関数のアドレスにINT3を設置する（後述） |
| `heap_disarm_hooks()` | 全フックを除去し待機状態をリセットする |
| `heap_handle_trap(regs)` | エントリトラップ処理（後述）。処理した場合1、しなかった場合0を返す |
| `heap_handle_finish_trap(regs)` | 確保完了トラップ処理（後述）。処理した場合1、しなかった場合0を返す |
| `heap_pending_finish()` | `heap_wait == HEAP_WAIT_RET` かつ `heap_finish_bp.active` が真であれば1を返す（確保関数の戻り待ち中かを判定するユーティリティ） |
| `show_heap()` | 生存中の確保記録をすべて一覧表示（`heap_trace_on` が偽の場合は使用方法を案内） |
| `show_leaks()` | 生存中の確保記録をリーク候補として一覧表示 |

### 12.3 フック設置 `heap_arm_hooks()`
1. `malloc`/`free`/`calloc`/`realloc` の名前について、優先順位 実シンボル（`lookup_symbol_entry`）→ PLT経由（`lookup_plt_symbol`）→ `<name>@plt` シンボル名 でアドレスを解決する（`lookup_heap_addr` 内部関数）
2. 見つかったアドレスに対し、`poke_byte` でINT3（0xCC）を書き込み、元の1バイトを `original_data` に退避してフックを `armed=1` で登録する
3. 1件もフックが設置できなかった場合はエラーメッセージを表示して -1 を返す
4. `heap_disarm_hooks()` は `disarm_heap_finish()` → `heap_wait = HEAP_IDLE` → 各フックの `restore_heap_hook` → `heap_hook_count = 0` の順でクリーンアップする

### 12.4 トラップ処理
- `heap_handle_trap(regs)`（エントリトラップ）
  1. `heap_trace_on` が偽、または `heap_wait != HEAP_IDLE`（既に確保待ち中）の場合は0を返す
  2. `regs->rip - 1` が登録フックアドレス（`find_heap_hook`）と一致するか判定。一致しなければ0を返す
  3. 一致すれば `hook->kind` に応じて分岐
     - `HEAP_HOOK_MALLOC`: `rdi`（サイズ）を記録して `heap_begin_wait` を呼び出す
     - `HEAP_HOOK_CALLOC`: `rdi`（nmemb）× `rsi`（size）= 合計バイト数を記録して `heap_begin_wait`
     - `HEAP_HOOK_REALLOC`: `rdi`（旧ポインタ）・`rsi`（新サイズ）を記録して `heap_begin_wait`
     - `HEAP_HOOK_FREE`: 即座に `heap_record_free(rdi)` で対応記録を非生存化（戻り値待ち不要）
  4. `step_over_heap_hook` でフック命令を1回通過させる。`heap_begin_wait` は `heap_get_return_address` でスタック先頭から戻り先アドレスを取得し `arm_heap_finish` で一時ブレークポイントを設置、`heap_find_call_site` で呼び出し元アドレスを推定して `heap_wait_site` に保存する
  5. 処理した場合は1を返し、`continue_execution`は表向きの停止を発生させず実行を継続する
- `heap_handle_finish_trap(regs)`（確保完了トラップ）
  1. `heap_wait != HEAP_WAIT_RET`、または `heap_finish_bp.active` が偽、または `regs->rip - 1 != heap_finish_bp.addr` の場合は0を返す
  2. `rax` を返却ポインタとして取得し、`heap_finish_bp` の一時ブレークポイントを解除（`uses_existing` が偽の場合のみ元データを書き戻す）
  3. `rewind_rip` で rip を補正し、`heap_wait = HEAP_IDLE` に戻す
  4. `heap_wait_kind` に応じて `heap_record_alloc`（malloc/calloc）または旧ポインタの `heap_record_free` → `heap_record_alloc`（realloc）を実行して確保記録を確定する
  5. 1を返して `continue_execution` に自動継続を指示する

### 12.5 表示
- `show_heap()` / `show_leaks()`: `heap_allocs[]`を走査し`live==1`のエントリのみ、通番・ポインタ値・サイズ・種別・呼び出し元file:line（取得できた場合）を一覧表示する。両者は同じデータソースを異なる見出しで表示するのみで、リークは「その時点で生存中の確保」として近似的に扱う
- `heap_on_process_exit()`: デバッギー終了検知時（`exec.c`の`continue_execution`から呼ばれる）に、`live`エントリ数を集計し、件数が1以上なら `[heap] N leak(s) at process exit`、0件なら `[heap] no leaks detected` のサマリを表示する（合計バイト数は表示しない）。`heap_trace_on` が偽の場合は何も表示しない

### 12.6 exec.cとの結合点
| 呼び出し元 | 呼び出し関数 | タイミング |
|---|---|---|
| `run_target` | `heap_reset()` → `heap_arm_hooks()`（トレース有効時のみ） | プロセス起動直後 |
| `continue_execution` のトラップハンドラ | `heap_handle_finish_trap` → `heap_handle_trap` | 各SIGTRAP停止時、ユーザーブレークポイント判定より前 |
| `continue_execution` の終了検知 | `heap_on_process_exit()` → `heap_disarm_hooks()` | `WIFEXITED`/`WIFSIGNALED`検知時 |

## 13. 例外・エラー処理詳細（共通方針の適用箇所）

| 分類 | 代表箇所 | 処理 |
|---|---|---|
| ptrace/システムコール失敗 | `memory.c`の`peek_word`/`poke_word`、`exec.c`の`waitpid` | `errno`判定 + `perror` + `-1`/`void`復帰 |
| 容量超過 | `set_breakpoint`（`bp_count>=MAX_BREAKPOINTS`）、`heap_record_alloc`（`heap_alloc_count>=MAX_HEAP_ALLOCS`）、`add_var_entry`、`load_symbols`のループ条件 | 事前チェックにより書き込みをスキップ。ブレークポイントのみ明示メッセージ、他は静かな打ち切り |
| 利用者エラー | `ui.c`の各コマンドハンドラ | `printf`での短文メッセージ、REPL続行 |
| パースエラー | `cmd_parse_line`, `expr_parse_ast`/bison版 | `errbuf`/静的エラーバッファへメッセージ格納、呼び出し元が表示 |
| プロセス終了 | `continue_execution` | `dbg.running=0`、ヒープサマリ表示のみで異常終了しない |
| 明示終了 | `ui.c`の`CMD_QUIT`処理 | `exit(0)` を唯一のプロセス終了経路とする |
